# 当前运行状态与验证边界

更新：2026-09-24。当前源码版本为 1.0.1 Beta；桌面门禁通过不代表手机稳定性验收完成。

## 当前路径

应用入口为 `minitool/index.html`，由 `scripts/build-minitool.py` 生成完整离线页面。当前默认关闭自动测光、开启 CineBloom 1/8 柔光和空间 DIR；不增加用户可选的柔光档位。导入长边最多 4096，冲印阶段不因设备慢而再次缩小输出。

柔光使用最长边 512 的光学场，优先 Float32 WebGL2 FFT，缺少能力时回退 CPU。空间 DIR 使用 GPU 分块短程卷积及最长边 512 的长尾场。它们是有界内存的近似，不能描述为全尺寸原生逐像素等价。仅半浮点设备的柔光继续使用 CPU；散射和 DIR 有各自半浮点路径。

## 验证与未完成项

`npm run verify:release` 在桌面浏览器检查完整构建、UI、导入、保存/分享、资源生命周期、色彩、颗粒、光学场、柔光及空间 DIR。照片与数值夹具由各检查脚本构造或从随仓基线读取，不依赖私人样片。

Android 空间 DIR 与 GPU 柔光已有小米浏览器 Chromium 135 / Adreno 830 测试记录；这不能替代小红书宿主或 iPhone 验收。GPU 柔光测试中 Tri-X 曾出现首轮总耗时约 170 秒，而柔光本身不足 0.2 秒，长等待仍待真机分段定位。当前微弱柔光默认值调整后，不能直接沿用之前标准强度的性能结论。

此前小红书 Android 与 iOS 的实况分享曾验证成功，但不代表最新渲染改动已在两平台全面验收。编码器启动、录制或自检失败会回退图片分享。

最新 iPhone Safari 冲印的“画布内存上限”提示已确认有误报：白色像素读回 253 而非 255，旧严格断言将轻微扰动当成分配失败。改为白/黑写入读回并允许微小误差，真正的空画布和恒定读回继续拦截；分配重试保留本张光学效果。手机随后连续完成 4 张 Portra 冲印并进入成片页，包含 4032×3024 与 3072×4096，GPU 柔光和空间 DIR 生效、没有分配重试。这是本次 Safari 冲印流程验证，不代表全部 iOS 机型、宿主或保存分享已验收；真正的资源不足仍可能导致初始化失败，错误诊断会保留原始原因。

最新包仍需在目标客户端完成单图/批量、取消、前后台、连续处理、保存与分享测试。公开源码文件清理、桌面测试与产品正式发布是分别验收的事项。
